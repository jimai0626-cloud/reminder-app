# リマインドちゃん

iPhone Shortcutsを使わずに、条件で内容が変わるリマインドをFitbitに届けるためのアプリ。
「iPhoneに確実に通知を出す」→ Fitbitアプリの通知ミラーリングが自動で腕に転送、という仕組み。
腕時計向けの特別な実装はしていない。

**Upstashやcron-job.orgのような、新しく登録するサービスは使っていない。**
使うのは今まで通りのVercelと、あなたが既に持っているGitHubアカウントだけ。
判定・送信のロジックはPythonで書いてある。

## 全体の仕組み（平たく言うと）

- **Vercel**：スマホに入れる「アプリの見た目」だけを置く場所（今まで通り）
- **GitHub**：2つの役目
  1. ルールを書いたファイルと、通知の宛先（購読情報）を保管する「メモ帳」
  2. 5分おきに「今送るものある？」と見に来る「見張り番」（GitHub Actions）
- **Python (`bot/send_reminder.py`)**：見張り番が来るたびに実際に判定・送信する頭脳部分

外部の知らないサービスは登場しない。かわりに、GitHubで「Secrets（秘密の保管庫）」と
「Actions（自動実行）」という、今まで使っていなかった機能を新しく使う。

## 重要な注意点（正直に先に書いておきます）

- **GitHubの無料の自動実行は、リポジトリに60日間まったく動きが無いと自動的に止まる仕様がある。**
  そのため、送信スクリプトは実行するたびに`bot/last-run.json`という小さな記録ファイルを
  書き換えてリポジトリにコミットするようにしてある。これにより「動きが無い」状態にならないので、
  普段は気にしなくて大丈夫。
- GitHubの無料の自動実行は「だいたい5分おき」ではあるものの、混雑時は数分〜数十分遅れることが
  公式にも案内されている。分刻みの厳密さが必須の通知には向かない。
- iOSのWeb Push購読は1〜2週間使われないと切れることがある。「絶対に見逃したくない通知」に
  使う場合は、月イチくらいでアプリを開いて購読が生きているか確認するのがおすすめ。
- iOSでpushが機能するのは、Safariの「ホーム画面に追加」でインストールしたあと、
  ホーム画面アイコンから開いた場合のみ。ブラウザのタブのままでは動かない。

## セットアップ手順

### 1. このフォルダをGitHubのリポジトリにする

GitHubで新しいリポジトリ（例: `reminder-app`、公開・非公開どちらでもOK）を作り、
このフォルダの中身をそこにpushする。GitHubのWeb画面から「Add file」→
「Upload files」でこのフォルダの中身をドラッグ&ドロップするだけでも作れる
（ただし `.github/workflows/send-reminder.yml` は隠しフォルダに入っているので、
Web画面からアップロードする場合はフォルダごとドラッグすれば一緒に入る）。

### 2. GitHubにSecretsを3つ登録する

そのリポジトリの `Settings → Secrets and variables → Actions → New repository secret`
から、以下の3つを登録する：

| Secret名 | 値 |
|---|---|
| `VAPID_PRIVATE_KEY_PEM` | `vapid-keys/private_key.pem` の中身をそのまま貼り付け |
| `VAPID_SUBJECT` | `mailto:自分のメールアドレス` |
| `PUSH_SUBSCRIPTION` | まだ空でOK（手順5で作った値を後から登録する） |

### 3. Vercelに環境変数を1つ設定してデプロイ

Vercelのプロジェクト設定 → Environment Variables に以下を追加する：

| 変数名 | 値 |
|---|---|
| `VITE_VAPID_PUBLIC_KEY` | `vapid-keys/info.txt` に書いてあるApplication Server Key |

Vercel側は今回サーバー機能（API）を使っていないので、これだけで動く。
GitHubのリポジトリと連携してデプロイすれば、今後 `bot/rules.json` を
GitHubの画面上で直接編集するだけでルールを更新できる（Vercel側の再デプロイは不要、
GitHub Actionsは実行のたびに最新のリポジトリの中身を読みに行くため）。

### 4. iPhoneにインストールして通知を許可する

デプロイ先のURLをSafariで開く → 共有ボタン → 「ホーム画面に追加」→
ホーム画面のアイコンから起動 → 「通知をオンにする」をタップして許可する。

### 5. 表示された購読情報をGitHub Secretsに貼り付ける

通知を許可すると、画面に長いコードが表示される。「コピーする」ボタンで
コピーし、手順2で作った `PUSH_SUBSCRIPTION` というSecretの値として貼り付ける
（Secretsは一度保存すると中身を見返せないので、貼り付け間違いに気づいたら
このコードをもう一度アプリで作り直せばOK）。

### 6. リマインドのルールを書く

`bot/rules.json` をGitHubの画面上で直接編集する（鉛筆マークのアイコンで
編集モードになる）。書き方は `bot/send_reminder.py` の冒頭コメントと、
以下の例を参考に：

```json
[
  {
    "id": "shift-checkin",
    "label": "シフト前チェック",
    "time": "07:30",
    "activeWeekdays": [1, 2, 3, 4, 5],
    "rotationGroup": {
      "anchorDate": "2026-09-01",
      "groupSize": 2,
      "activeIndex": 0
    },
    "message": {
      "title": "窓口シフトの準備",
      "body": "配布物と受付リストを確認してください"
    }
  }
]
```

`activeWeekdays` は 0=日, 1=月, 2=火, 3=水, 4=木, 5=金, 6=土。
`rotationGroup` は「2週間おきの当番」のような周期的な条件のときだけ指定する
（毎日/毎週固定でよければ `activeWeekdays` だけで十分、この項目自体を省略してよい）。

### 7. Fitbit側の設定を確認

Fitbitアプリ → 通知設定で、このアプリからの通知（または「すべての通知」）が
オンになっているか確認する。ここがオフだと、iPhoneには通知が来ていても
腕には振動しない。

### 8. 動作テスト

保存を待たなくても、GitHubのリポジトリの「Actions」タブ →
「send-reminder」ワークフロー → 「Run workflow」ボタンで今すぐ1回実行できる。
実行後、`bot/last-run.json` に結果（何件チェックして何件送ったか）が
記録されるので、そこで様子を確認できる。

## 今後拡張するなら

- ルールが増えてJSONを手で書くのがつらくなったら、簡単な管理画面をVercel側に
  足すこともできる（そのときはあらためて相談を）。
- 複数端末に送り分けたい場合は、`PUSH_SUBSCRIPTION` を1つではなく
  端末ごとに分けて `bot/rules.json` 側でどの端末に送るか指定する形に拡張する。
